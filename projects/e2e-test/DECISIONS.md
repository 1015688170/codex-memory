# Decisions

- Keep functional and performance suites separately runnable, while reusing shared Playwright flows such as authentication and Bag loading. Keep their reports in separate directories.
- Group functional cases by the actual value of the spreadsheet's `Category` column, not the literal word `Category`. A test title containing several TC IDs is one combined automated case.
- For future functional cases, first provide manual steps and incorporate the user's observed UI behavior before implementing. Defer cases whose verdict requires human screenshot inspection, known-bug cases, and dataset-loading cases. Diagnostic screenshots generated by automation are not a manual verdict.
- Performance reports currently present measurements without a pass/fail performance threshold. The default is one round, configurable with `PERFORMANCE_ROUNDS`; Bag frame counts must be discovered rather than hard-coded.
- Generated `reports/` files are outside AOCI's managed index. Keep the AOCI MCP configuration project-local rather than assuming every Codex chat on the server loads it.
