# Knowledge

- `config/case-status.ts` is the runtime case registry and source for the functional scope filter. `E2E_CASE_SCOPE=completed` is the default; `all` currently selects the same completed cases, while `pending` selects pending cases. The Excel workbook is not read during execution. The existing `README.md` still says only one business case is completed and is stale on that point.
- Functional suite entry: `npm run test:e2e`; performance suite entry: `npm run test:performance`. See `README.md` and `PERFORMANCE_TEST_GUIDE.md` for Docker commands and report paths. Do not persist `.env` values in memory.
- `P-02-001` excludes the `0 -> 1` and `1 -> 2` cold-start transitions from steady-state interval statistics, requires at least 200 consecutive-frame samples per round, and records skipped frames separately. `P-02-002` observes frame jumps from frame 0 to the dynamically discovered final frame. Both require all configured rounds to complete collection.
- In `specs/new/plot-table-creation.spec.ts`, Raw Plot creation accepts either a rendered series with at least three points or a visible Retry state whose tooltip reports `PLOT_BOUNDS_NOT_READY` with the explanatory cache error. Do not apply the three-point criterion to the error branch.
- `AGENTS.md` in the test project contains the AOCI operating contract. A VS Code terminal `cd` does not change an existing Codex chat's recorded working directory or load project-local MCP tools into that chat. Open a Codex chat rooted at the trusted project to use its AOCI MCP configuration; ordinary file work can still target the project by explicit path.
